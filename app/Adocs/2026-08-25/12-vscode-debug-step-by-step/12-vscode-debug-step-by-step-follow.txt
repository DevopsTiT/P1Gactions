========== ENGLISH (full follow) ==========

WHAT DEBUGGING IS
- Pause your program on a line you choose.
- Inspect variables (see real values).
- Step line by line (Over / Into / Out) until you see the bug.
- Better than print alone: you get Variables, Watch, Call Stack.

PREREQUISITES
1) File → Open Folder… (project root). Do NOT rely on a single loose file.
2) Language tools:
   - Python: install Python extension; pick interpreter in status bar.
   - Node/JS: Node on PATH; built-in JS debugger is usually enough.
3) You will create .vscode/launch.json (how the editor starts under the debugger).

CREATE launch.json
1) Open Run and Debug (left: play+bug icon), or View → Run.
2) Click “create a launch.json file”.
3) Pick Python File or Node.js.
4) Edit later if needed: program, cwd, args, env.
   Companion samples:
   - 12-vscode-debug-step-by-step-launch-python.json
   - 12-vscode-debug-step-by-step-launch-node.json
   Copy/merge into .vscode/launch.json.

KEY UI
- Run and Debug sidebar: start configs.
- Breakpoints: red dots in the gutter (left of line numbers).
- Variables: values while paused.
- Watch: expressions you care about.
- Call Stack: which function called which.
- Debug Console: evaluate expressions while paused.
- Toolbar: Continue, Step Over/Into/Out, Restart, Stop.

CONTROLS
| Action      | Shortcut (typical) | Meaning                                      |
|-------------|--------------------|----------------------------------------------|
| Continue    | F5                 | Run until next breakpoint                    |
| Step Over   | F10                | Next line; do not enter functions            |
| Step Into   | F11                | Enter the function on this line              |
| Step Out    | Shift+F11          | Finish current function; back to caller      |
| Restart     | toolbar            | Start the same debug config again            |
| Stop        | Shift+F5 (often)   | End debug session                            |

Beginner tip: prefer F10; use F11 only for your own functions.

BREAKPOINTS
- Click gutter → red dot (always pause).
- Click again → remove.
- Right-click → Conditional Breakpoint → e.g. i == 3 or name == "Lin".

PYTHON — STEPS
1) Open Folder (project).
2) Install Python extension; select interpreter.
3) Create app.py (sample below).
4) Run and Debug → create launch.json → Python File (or paste companion JSON).
5) Breakpoint on a line that will run.
6) Press F5 (not “run in terminal only”).
7) Use Variables / Watch / Debug Console.
8) F10 / F11 / Continue / Stop.

app.py sample:
  def greet(name):
      message = f"hello, {name}"
      return message

  def main():
      names = ["Ada", "Lin"]
      for n in names:
          print(greet(n))  # breakpoint here

  if __name__ == "__main__":
      main()

NODE/JS — STEPS
1) Open Folder.
2) Confirm node works in a terminal.
3) Create index.js (sample below).
4) launch.json → Node.js (or companion JSON).
5) Breakpoint → F5 → Variables / Watch → step controls.

index.js sample:
  function greet(name) {
    const message = `hello, ${name}`;
    return message;
  }
  function main() {
    const names = ["Ada", "Lin"];
    for (const n of names) {
      console.log(greet(n)); // breakpoint here
    }
  }
  main();

MINIMAL launch.json (Python)
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Python: Current File",
      "type": "debugpy",
      "request": "launch",
      "program": "${file}",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}"
    }
  ]
}

MINIMAL launch.json (Node)
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Node: Current File",
      "type": "node",
      "request": "launch",
      "program": "${file}",
      "cwd": "${workspaceFolder}",
      "console": "integratedTerminal"
    }
  ]
}

COMMON MISTAKES
- Wrong cwd → set "cwd": "${workspaceFolder}".
- Breakpoint never hits → use F5 debug; ensure line runs; correct file.
- Running without debug → terminal-only run will not pause.
- Launch vs Attach → Launch starts the app (beginner default); Attach connects to an already running process.
- Single file / no folder → Open Folder first.
- Wrong Python interpreter → pick the right env in the status bar.

DECISION TREE (short)
code wrong → Open Folder? → extension? → launch.json? → breakpoint → F5
  hit? → inspect + step
  miss? → cwd / path / launch vs attach / really executed?

========== 中文（完整跟做） ==========

调试是什么
- 在你指定的那一行把程序“暂停”。
- 查看变量真实值。
- 一行行往前走（步过 / 步入 / 步出），直到看清 bug。
- 比只写 print 更强：有变量、监视、调用堆栈。

开始前准备
1) 文件 → 打开文件夹…（项目根目录）。不要只开一个零散单文件。
2) 语言支持：
   - Python：安装 Python 扩展；状态栏选解释器。
   - Node/JS：终端能跑 node；一般用内置 JS 调试即可。
3) 会生成 .vscode/launch.json（告诉编辑器如何用调试器启动）。

创建 launch.json
1) 打开“运行和调试”（左侧播放+虫子图标），或 查看 → 运行。
2) 点“创建 launch.json 文件”。
3) 选 Python File 或 Node.js。
4) 以后可改 program、cwd、args、env。
   同目录示例：
   - 12-vscode-debug-step-by-step-launch-python.json
   - 12-vscode-debug-step-by-step-launch-node.json
   复制或合并进 .vscode/launch.json。

界面要认这些
- 运行和调试：启动配置。
- 断点：行号左侧红点。
- 变量：暂停时的值。
- 监视：你关心的表达式。
- 调用堆栈：谁调用了谁。
- 调试控制台：暂停时算表达式。
- 工具栏：继续、步过/步入/步出、重启、停止。

控制键
- 继续：F5（跑到下一个断点）
- 步过：F10（下一行，不进入函数）
- 步入：F11（进入当前行调用的函数）
- 步出：Shift+F11（跑完当前函数回到上层）
- 重启 / 停止：工具栏（停止常见为 Shift+F5）

新手建议：多用 F10；只有要查自己写的函数时再用 F11。

断点
- 点行号左侧 → 红点（总是停）。
- 再点一次 → 去掉。
- 右键 → 条件断点 → 例如 i == 3 或 name == "Lin"。

Python 跟做
1) 打开文件夹。
2) 装 Python 扩展并选解释器。
3) 写 app.py（见上文英文样例）。
4) 运行和调试 → 创建 launch.json → Python File。
5) 在会执行到的行打断点。
6) 按 F5（不要只用终端裸跑）。
7) 看变量 / 监视 / 调试控制台；用 F10、F11、继续、停止。

Node/JS 跟做
1) 打开文件夹。
2) 确认 node 可用。
3) 写 index.js。
4) launch.json 选 Node.js。
5) 断点 → F5 → 变量/监视 → 单步。

常见坑
- cwd 不对 → "cwd": "${workspaceFolder}"
- 断点不停 → 必须用调试启动 F5；确认这行真的会执行；文件对不对。
- 没用调试跑 → 纯终端运行不会进变量面板。
- Launch 与 Attach → 新手用 Launch（由编辑器启动）；Attach 是连已在跑的进程。
- 没开文件夹 → 先 Open Folder。
- Python 解释器错了 → 状态栏换对虚拟环境。

判断树（短）
程序不对 → 开了文件夹？ → 扩展好了？ → 有 launch.json？ → 断点 → F5
  停住了 → 看变量并单步
  没停 → cwd / 路径 / Launch还是Attach / 代码是否跑到
