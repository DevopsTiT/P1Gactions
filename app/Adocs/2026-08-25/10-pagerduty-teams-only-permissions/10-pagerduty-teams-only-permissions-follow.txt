ENGLISH — Teams-only permission checklist for 4 AI Agents POC
================================================================================

Verdict
- Teams-only POC is realistic for: SRE Agent (Early Access), Scribe Agent, Insights Agent (on-demand chat).
- Shift Agent is Slack-preferential (docs + pricing say Slack; Slack notification rules). Do not expect full Shift help in Teams.
- Insights proactive recommendation DMs are still documented as Slack DMs; Teams gets conversational Insights.

Decision tree
```
Need agents in Teams only (no Slack)?
  → Have PD Admin/Owner AND Microsoft Admin? no → blocked
  → Install PagerDuty Teams app → PD Authorize → Graph Admin consent
  → AI Settings: Teams Connected + Optional Advance perms + Teams Enabled
  → SRE (EA) / Scribe / Insights chat = OK
  → Shift / Insights proactive DMs = Slack-first → defer or use web
```

----------------------------------------
A) People / roles (who does what)
----------------------------------------

PagerDuty
| Who | Permission / role | What they do for POC |
|-----|-------------------|----------------------|
| Account Owner / Global Admin | Enable/disable AI agents; Advance team access | Turn SRE/Scribe/Insights on; scope to one PD team |
| Admin (or Owner) | Authorize Teams connection | Connect PD ↔ Teams tenant/team |
| Manager | Map service ↔ channel (in Teams app) | Point test Service at POC channel |
| Responder / any user | Linked PD↔Teams account; on a team with Advance access | Ask agents, ack/resolve, add Scribe |
| Non-admin user | “Request to Admin” on agent card | Emails admins to enable an agent |

Microsoft
| Who | What they must do |
|-----|-------------------|
| Teams Admin | Allow third-party apps so PagerDuty app can be installed |
| Microsoft Admin (typically Global Admin for org-wide Graph admin consent) | Accept Graph Application / Delegated permissions; or run bot command `appconnect` |
| Meeting policy admin (optional) | CsApplicationAccessPolicy for application-token meeting create; lobby settings for Scribe auto-admit |

----------------------------------------
B) Consent model (admin vs user)
----------------------------------------

| Type | Who consents | When needed |
|------|--------------|-------------|
| Application permissions | Microsoft Admin, once | Background automation: create chat, add members, create meetings, ChatMessage.Read.All for Advance |
| Delegated permissions | Tenant allows app; each user runs `graphAuth` in PagerDuty bot DM | Act-as-user path; required if Application for that feature is revoked/missing |
| Hybrid (PD default) | Both can exist | PD tries Application first, falls back to Delegated |
| PD↔Teams user link | Each user: `linkUser` | Required for incident actions and auto-add to chats/meetings — separate from Graph |

POC recommendation: prefer Application + Admin consent once for fewer blockers; still have POC users run `linkUser`. Only force everyone through `graphAuth` if security requires Delegated-only.

----------------------------------------
C) Microsoft Graph scopes — POC least privilege
----------------------------------------

Must for useful Advance / agents in Teams
- Application: ChatMessage.Read.All
- and/or Delegated: ChatMessage.Read
(Also enable “Optional Permissions for PagerDuty Advance” in Teams per Advance setup doc.)

Baseline for incident chat + meetings (Application path — good for POC)
- Chat.Create
- ChatMember.ReadWrite.All
- TeamsAppInstallation.ReadWriteSelfForChat.All
- OnlineMeetings.ReadWrite.All
- Organization.Read.All
- User.ReadBasic.All (optional but useful for auto-add responders; prefer over User.Read.All)

Baseline Delegated equivalents (if not using Application)
- Chat.ReadWrite
- TeamsAppInstallation.ReadWriteForChat
- User.ReadBasic.All
- OnlineMeetings.ReadWrite
- Channel.Create (also Application)
- User.Read + openid + profile + email

Prefer NOT to grant for least privilege
- User.Read.All (revoke; use User.ReadBasic.All)
- Calendars.ReadWrite unless meeting create needs calendar-event fallback

Hard product limits
- No private or shared Teams channels for the PagerDuty app
- Dedicated private incident chats via Incident Workflows are OK

US AppId for meeting access policy (if needed): 05ffe668-5b27-45ff-a64d-b2ed6c475d7a
EU AppId: 8f79a561-d2f1-4a1e-8092-c2039043a40e

----------------------------------------
D) Per-agent checklist (Teams-only)
----------------------------------------

1) SRE Agent
- Teams: Early Access
- Need: Advance → Teams Connected + Enabled; SRE Agent Enabled; optional Advance message read scopes
- Use: @pagerduty <question> in Teams chat
- PD role: Admin enables; responders with Advance team access use it
- POC: YES on Teams-only

2) Scribe Agent
- Teams: Supported for transcript delivery AND joining Teams meetings
- Need: Advance Teams on; Scribe Enabled; Teams integration for auto-launch/workflows; optional lobby bypass
- Use: @PagerDuty advance scribe → Add Scribe Agent to meeting
- Limitation: cannot join registration/CAPTCHA meetings; may show “Unverified” (cosmetic)
- POC: YES on Teams-only (strongest fit)

3) Insights Agent
- Teams: Conversational Insights GA on Teams (changelog May 2026)
- Need: Advance Teams on; Insights usually auto-on with Advance
- Use: @pagerduty <analytics question> in channel or Advance chat
- Gap: Proactive recommendation DMs documented for Slack (Managers/Admins/Owners) — do not rely on Teams DMs for that
- POC: YES for on-demand Q&A; NO/partial for proactive DM maturity tips

4) Shift Agent
- Teams: Limited / Slack-first
- Docs: “By default… enable PagerDuty Advance with the Slack integration”; configure “for example, Slack”; Slack notification rules for conflicts/coverage
- Pricing: “Available in Slack”
- POC: DEFER on Teams-only (use PD web + Google Calendar extension for conflict awareness, or add Slack later)

----------------------------------------
E) Ordered enablement (POC)
----------------------------------------

1. Teams Admin: allow PagerDuty third-party app
2. Install PagerDuty (or PagerDuty EU) → Add to one Team → PD Admin Authorize
3. Microsoft Admin: Authorize Graph / Accept scopes (or `appconnect`)
4. Confirm Advance optional permissions (ChatMessage.Read / ChatMessage.Read.All)
5. PD web: Integrations → Microsoft Teams → connect one channel ↔ test Service
6. AI → AI Settings → Assistant and AI Agents → Teams Connected → Enabled
7. Enable agents: SRE, Scribe, Insights (skip Shift or note Slack gap)
8. Scope Advance access to one PD team
9. Each POC user: linkUser (and graphAuth if Delegated)
10. Optional: meeting access policy PowerShell; Scribe lobby auto-admit

----------------------------------------
F) Teams bot commands (users)
----------------------------------------

linkUser
graphAuth
appconnect          (Microsoft Admin)
@PagerDuty advance <question>
@PagerDuty advance scribe
@pagerduty <SRE or Insights question>

中文 — 仅用 Microsoft Teams 时的权限清单（4 个 AI Agents POC）
================================================================================

结论
- 仅 Teams、不用 Slack：可以做 SRE（早期访问）、Scribe、Insights（对话问答）POC。
- Shift：文档与定价偏 Slack（冲突/代班通知走 Slack）。Teams-only 不要按完整 Shift POC 规划。
- Insights 主动推荐私信：文档仍写 Slack DM；Teams 侧以对话查询为主。

决策树
```
只用 Teams？
  → 没有 PD Admin/Owner + Microsoft Admin？→ 卡住
  → 安装 PagerDuty Teams 应用 → PD 授权 → Graph 管理员同意
  → AI Settings：Teams Connected + Advance 可选权限 + Teams Enabled
  → SRE / Scribe / Insights 对话 = 可以
  → Shift / Insights 主动 DM = 优先 Slack → 延后或改用网页
```

----------------------------------------
A) 人员与角色
----------------------------------------

PagerDuty
| 角色 | 权限作用 | POC 用途 |
|------|----------|----------|
| Account Owner / Global Admin | 开关 AI Agents、Advance 团队范围 | 打开 SRE/Scribe/Insights，限制到一个 PD team |
| Admin | 授权连接 Teams | 完成 PD ↔ Teams 租户/团队绑定 |
| Manager | 在 Teams 里映射 Service ↔ Channel | 测试服务接到 POC 频道 |
| 响应人（已 link） | 在有 Advance 权限的团队上使用 Agents | 提问、确认、拉 Scribe |
| 非管理员 | Request to Admin | 邮件请管理员打开某个 Agent |

Microsoft
| 角色 | 必须做什么 |
|------|------------|
| Teams Admin | 允许第三方应用，才能安装 PagerDuty |
| Microsoft Admin（组织级 Graph 同意通常需 Global Admin） | 同意 Graph 应用/委派权限；或对机器人发 `appconnect` |
| 会议策略管理员（可选） | 应用令牌创建会议的 CsApplicationAccessPolicy；Scribe 绕过大厅 |

----------------------------------------
B) 管理员同意 vs 用户同意
----------------------------------------

| 类型 | 谁同意 | 何时需要 |
|------|--------|----------|
| Application（应用程序权限） | Microsoft Admin，一次 | 后台建聊天、加人、建会议、ChatMessage.Read.All 供 Advance |
| Delegated（委派权限） | 租户允许后，用户在机器人私聊跑 `graphAuth` | “以用户身份”路径；撤销 Application 后必备 |
| Hybrid（混合，当前默认） | 可并存 | 有 Application 先用它，否则回退 Delegated |
| PD↔Teams 账号关联 | 每人 `linkUser` | 与 Graph 分开；做动作、自动进会/进聊天需要 |

POC 建议：优先 Application + 管理员一次同意；POC 用户仍要 `linkUser`。只有安全要求“必须委派”时才全员 `graphAuth`。

----------------------------------------
C) Graph 权限 — POC 最小权限
----------------------------------------

Advance / Agents 在 Teams 里真正有用时必给
- Application：ChatMessage.Read.All
- 和/或 Delegated：ChatMessage.Read
（按 Advance 文档在 Teams 里加上 Optional Permissions for PagerDuty Advance）

Application 基线（适合 POC 少折腾）
- Chat.Create
- ChatMember.ReadWrite.All
- TeamsAppInstallation.ReadWriteSelfForChat.All
- OnlineMeetings.ReadWrite.All
- Organization.Read.All
- User.ReadBasic.All（自动加人时有用；优先于 User.Read.All）

不要轻易给
- User.Read.All（可撤；改用 User.ReadBasic.All）
- Calendars.ReadWrite（除非建会失败需要日历回退）

产品硬限制
- 不能装到 Teams 的 private / shared channel
- Incident Workflow 建专用事故私聊仍然可以

会议策略 AppId：美区 05ffe668-5b27-45ff-a64d-b2ed6c475d7a；欧区 8f79a561-d2f1-4a1e-8092-c2039043a40e

----------------------------------------
D) 按 Agent（仅 Teams）
----------------------------------------

1) SRE Agent
- Teams：Early Access
- 需要：Advance Teams 已连并启用；SRE Enabled；Advance 读消息权限
- 用法：@pagerduty + 问题
- POC：可以（Teams-only）

2) Scribe Agent
- Teams：支持把转录发到 Teams，并加入 Teams 会议
- 需要：Advance Teams；Scribe Enabled；自动加入需 Teams 集成；可选大厅放行
- 用法：@PagerDuty advance scribe
- 限制：需报名/验证码的会进不去；可能显示 Unverified（不影响功能）
- POC：强烈推荐（Teams-only 最合适）

3) Insights Agent
- Teams：对话问答已 GA
- 需要：Advance Teams；Insights 通常随 Advance 开启
- 用法：频道或 Advance 聊天里 @pagerduty 提问
- 缺口：主动推荐私信文档仍写 Slack
- POC：对话问答可以；主动 DM 成熟度建议不要指望 Teams

4) Shift Agent
- Teams：有限 / 优先 Slack
- 文档默认随 Slack 开 Advance 激活；冲突/代班通知规则绑定 Slack
- 定价写 Available in Slack
- POC：Teams-only 建议延后（可用网页排班 + Google Calendar，或以后加 Slack）

----------------------------------------
E) 启用顺序（POC）
----------------------------------------

1. Teams Admin 允许 PagerDuty 第三方应用
2. 安装 PagerDuty → 加到一个 Team → PD Admin Authorize
3. Microsoft Admin 同意 Graph（或 `appconnect`）
4. 确认 Advance 可选权限（ChatMessage.Read / ChatMessage.Read.All）
5. PD：Integrations → Microsoft Teams → 一个频道 ↔ 测试 Service
6. AI → AI Settings → Teams Connected → Enabled
7. 打开 SRE、Scribe、Insights（Shift 先跳过或标注 Slack 缺口）
8. Advance 权限限制到一个 PD team
9. 每人 linkUser（Delegated 时再 graphAuth）
10. 可选：会议 access policy；Scribe 大厅自动准入

----------------------------------------
F) Teams 机器人命令
----------------------------------------

linkUser
graphAuth
appconnect
@PagerDuty advance <问题>
@PagerDuty advance scribe
@pagerduty <SRE 或 Insights 问题>
