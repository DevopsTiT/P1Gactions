ENGLISH — Single ordered Teams-only runbook (all 4 agents)
================================================================================

Decision tree
- Active incident triage / RCA / runbook? → SRE Agent (Teams Early Access)
- Incident bridge / PIR notes? → Scribe Agent (Teams meeting + chat)
- On-call OOO / coverage? → Shift Agent = Slack-first → Path B (PD web + Calendar) or Path A best-effort
- Ops health / MTTR trends? → Insights Agent (conversational in Teams); weekly DMs still Slack-first

AI Actions cheat sheet
- SRE Agent: 4 Actions per ask or nudge
- Scribe Agent: ~6 per 30 min of meeting + ~2 for final summary
- Shift Agent: 0
- Insights Agent: 0

Safe demo rule
- Service poc-pd-ai-agents-test with escalation that pages ONLY you
- Shift: Level-1 TEST schedule only — never prod primary

8) Optional: scope Advance to one PD team that owns the test Service
9) Each user in Teams: @PagerDuty linkUser (and graphAuth if Delegated-heavy)

    - US AppId 05ffe668-5b27-45ff-a64d-b2ed6c475d7a
    - EU AppId 8f79a561-d2f1-4a1e-8092-c2039043a40e

Success criteria (§0)

- AI Settings shows Teams Connected/Enabled

1) SRE Agent POC — full click/say steps in Teams
================================================================================

POC goal
Prove SRE Agent summarizes a TEST incident in Microsoft Teams, uses a small runbook, and suggests next steps with human approval before remediation.

Prerequisites
- §0 complete; SRE Agent Enabled; Teams Early Access available
- Test Service mapped to POC channel
- Runbook .md/.txt under 100 KB
- Optional: one real connector (Grafana/Datadog/New Relic/CloudWatch/Confluence/GitHub)
- Optional web: Incident SRE Agent tab; Ops Console needs AIOps + Advance

Numbered steps
1) Optional: AI Settings → SRE Agent → add one real connector (Dynatrace usually creates the incident; not the main connector list)
2) Write runbook poc-checkout-latency.md (5–10 steps: check deploy, problem URL, named rollback)
3) PD web: Create low-risk test incident on poc-pd-ai-agents-test (UI Create incident — no prod routing key)
4) Open mapped Teams channel (or dedicated incident chat); confirm incident card
5) In Teams type: @pagerduty What are some likely root causes?
6) Upload/Update Runbook when offered (or use PD web Incident → SRE Agent tab if Teams EA lacks upload) → Submit .md
7) Ask: @pagerduty Analyze past incidents
8) Ask: @pagerduty What steps should I take first?
9) If workflow/remediation offered: READ it; approve or decline — do not auto-run on prod
10) Optional: Incident details → SRE Agent tab; or AIOps → Operations Console → incident → SRE Agent tab
11) Resolve the test incident so service memory can save

Success criteria
- Grounded triage reply in Teams (or web tab)
- Later answer references uploaded runbook
- No remediation without explicit confirm
- After resolve, follow-up asks feel more specific

Safety
- Test Service only
- Human confirms remediations
- Fact-check claims in monitoring / deploy tools
- Only first ~2000 characters of custom_details/notes analyzed
- No customer PII in questions (channel-visible)

Cost
- 4 AI Actions per chat ask or nudge

2) Scribe Agent POC — Teams meeting path
================================================================================

POC goal
Prove Scribe joins a short Microsoft Teams meeting on a TEST incident, captures transcript, and posts a post-meeting summary visible in Teams (no Slack).

Prerequisites
- §0 complete; Scribe Enabled; meeting Graph scopes OK
- Teams meeting URL with passcode in URL when required
- Someone joins within 15 minutes for auto-join
- Optional: lobby bypass for Scribe bot

Numbered steps
1) Confirm Scribe Agent Enabled (US often manual toggle; EU may default on)
2) Optional: Incident Workflow step “Add Scribe Agent” on test Service
3) Create test incident on poc-pd-ai-agents-test
4) Create/open short Teams meeting; copy join URL (+ passcode)
5) Paste conference URL onto incident meeting field in PagerDuty
6) Open linked Teams incident channel/chat
7) Wait for auto-join OR type: @PagerDuty advance scribe → Add Scribe Agent to meeting → confirm URL
8) Join the meeting yourself within 15 minutes; admit Scribe from lobby if needed
9) Speak 2–3 clear lines: symptom, suspected cause, decision (e.g. rollback if error rate stays high)
10) End the meeting
11) Confirm transcript activity in Teams (if chat delivery on)
12) Confirm post-meeting summary: decisions, action items, attendees
13) Optional: ask Advance for Post-Incident Review draft; check bridge context
14) Resolve the test incident

Success criteria
- Scribe joins the Teams meeting
- Transcript reflects spoken content
- Wrap-up lists decisions / actions / attendees
- PIR/status draft can reuse bridge context

Safety
- Test incident + short meeting only
- Warn attendees they are being transcribed
- Limit: 1 Scribe per meeting; up to 10 concurrent meetings account-wide
- Keep POC under ~10 minutes

Cost
- ~6 AI Actions per 30 minutes of bridge + ~2 when final summary posts

3) Shift Agent — honest Teams-only (Path A best-effort OR Path B recommended)
================================================================================

Honest status
- Shift is Slack-first (docs + pricing + Slack notification rules for conflict/coverage)
- Do NOT expect full “Request coverage → teammate accepts in Teams DM”
- Still give a step path: Path A (best-effort) or Path B (PD web + Calendar — recommended)

Prerequisites (both paths)
- Level-1 schedule only (by design)
- Test schedule poc-shift-agent — never prod primary
- Google Calendar Extension recommended (Admin/Owner configures)
- Two people only needed if you try coverage coordination; Path B needs you + optional coverage person for override

----- Path A — best-effort Teams-only workaround -----
1) Enable Shift Agent toggle if off
2) Create test schedule poc-shift-agent; you primary on a known near-term window
3) Attach schedule to Level 1 of a TEST escalation policy
4) Admin enables Google Calendar Extension; you authorize calendar
5) Block OOO on Google Calendar overlapping that window
6) In Teams Advance chat ask: I am on vacation <date>. Do I have a conflict?
   (or @PagerDuty advance I am OOO <date>. Any on-call conflict?)
7) If conflict shown and Request coverage offered: understand teammate accept may need Slack
8) Manual close: PD web → Schedules → poc-shift-agent → create override for teammate → confirm history
9) Result: PARTIAL if conflict visible; FULL Shift coverage chat = blocked without Slack

----- Path B — skip full Shift / PD web + Calendar (recommended) -----
1) Document: “Full Shift Agent Slack DM POC deferred — Teams-only org.”
2) Create test schedule poc-shift-agent; you primary on a known window
3) Attach to Level 1 of TEST escalation policy (not prod)
4) Admin enables Google Calendar Extension; you authorize calendar
5) Create OOO block overlapping on-call window
6) In PD web, confirm overlap via Calendar extension / schedule UI
7) Create schedule override for coverage person for that window
8) Confirm override in schedule history
9) Optional later: when Slack exists, re-run seq 9 Shift POC for Request coverage → accept DMs

Success criteria
- Path A: conflict language in Teams OR documented miss; manual override written
- Path B: OOO handled with Calendar + web override; audit trail exists; Slack path explicitly deferred
- No overrides on production primary

Safety
- Test schedule / test EP only
- Tell candidate it is a POC
- Level-1 only by design (lower levels will not show Shift conflicts)
- Do not claim Teams DM coverage worked

Cost
- 0 AI Actions

7) Sanity-check answers against Analytics in PD web for the same window
8) Optional: Rate AI Response if shown

Success criteria
- Number or trend reply in Teams tied to your Team/Service
- Roughly matches Analytics UI
- Channel members can see the reply
- Notes state weekly proactive DMs are Slack-first

Safety
- No customer PII in questions
- Apply any config tips on test first
- Empty history → thin answers; pick a service with data

- 0 AI Actions

中文摘要 — Teams-only 四 Agent 有序 POC
================================================================================

结论
- 只用 Microsoft Teams（不用 Slack）时：SRE、Scribe、Insights（对话问答）可做完整 POC。
- Shift 以 Slack 为主；Teams-only 请走 Path B（PD 网页排班 + Google Calendar 手动 override），或 Path A（Teams 里试问冲突，覆盖接受仍可能缺 Slack）。
- Insights 每周主动成熟度私信仍以 Slack 为主；Teams 只证明现场提问。

决策树
- 活跃故障排查 → SRE Agent
- 桥接会议纪要 / PIR → Scribe Agent
- 值班冲突 / 换班 → Shift（Path B 推荐）
- 运营健康 / MTTR → Insights（Teams 对话）

0) 共享启用（只做一次）
1. Teams 管理员允许 PagerDuty 应用
2. 安装并加入一个 POC 团队 → PD 管理员 Authorize
3. Microsoft 管理员 Graph 同意（Advance 需消息读取权限）
4. 频道映射测试服务 poc-pd-ai-agents-test（升级策略只叫你）
5. AI Settings：Teams Connected / Enabled；打开 SRE、Scribe、Insights
6. 每人在 Teams：@PagerDuty linkUser（必要时 graphAuth）

1) SRE Agent（Teams）
- 在测试服务建事件 → Teams 频道 @pagerduty 问根因
- 上传 runbook → 再问 past incidents / first steps
- 有修复建议必须人工确认；最后 Resolve
- 费用：每次提问/轻推 4 AI Actions

2) Scribe Agent（Teams 会议）
- 事件填 Teams 会议 URL → @PagerDuty advance scribe 或等自动加入
- 15 分钟内进会；说清症状/原因/决定；结束会议看摘要
- 费用：约每 30 分钟 ~6 + 最终摘要 ~2；POC 控制在约 10 分钟内

3) Shift Agent（诚实说明）
- 完整「请求覆盖 → Slack 接受」在 Teams-only 不可靠
- Path B（推荐）：日历冲突 → PD 网页手动 override → 看历史记录
- Path A：Teams Advance 试问冲突，再用网页写 override
- 费用：0

4) Insights Agent（Teams 对话）
- @pagerduty 问上周高紧急数量、6 个月 MTTR、MTTA 环比
- 用 Analytics 网页核对
- 每周主动建议私信：仍算 Slack；Teams-only 记缺口即可
- 费用：0

安全总原则
- 只用测试服务 / Level-1 测试排班；不对生产排班写 override
- 不把客户 PII 打进频道提问
- 不自动跑生产修复；Scribe 会前提醒录写

不自动执行 live API；不 push。用户明确要求后再跑命令或上传。
