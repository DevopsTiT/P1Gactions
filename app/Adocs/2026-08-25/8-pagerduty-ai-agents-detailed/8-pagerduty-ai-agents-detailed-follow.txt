ENGLISH — What are the 4 PagerDuty AI agents, and how to use each

Verdict
- Yes: PagerDuty officially markets exactly **4 AI agents** (Fall 2025 end-to-end AI agent suite).
- Names: **SRE Agent**, **Scribe Agent**, **Shift Agent**, **Insights Agent**.
- Umbrella: **PagerDuty Advance** (platform + AI Actions + Advance Assistant). Advance is NOT a fifth “agent”; the Assistant routes chat to these agents.
- Not in the “4 agents” count: Event Intelligence / noise reduction, status-update drafts, Automation Digest, AI-generated runbooks (related Advance/AIOps features).

Which agent for which job
- Live incident triage / root cause / runbook / remediation → SRE Agent
- Bridge transcript + meeting summary + better PIR → Scribe Agent
- On-call conflict / find coverage / overrides → Shift Agent
- Trends, MTTA/MTTR questions, weekly maturity tips → Insights Agent

Enable once (Admin / Global Admin / Account Owner)
1) PagerDuty web → AI → AI Settings → Assistant and AI Agents Configuration
2) Connect Slack and/or Microsoft Teams; toggle on
3) Under AI Agents, toggle Enabled: SRE, Scribe, Shift, Insights
4) If you lack permission: click Request to Admin next to the agent

---
1) SRE Agent — virtual responder

What it is
- AI helper that reads the incident, past/related incidents, runbooks, change events, and connected logs, then suggests next steps (and can recommend/run approved workflows). Builds per-service memory after resolve.

When to use
- Right after a page when you would otherwise hunt Confluence and dashboards for 15 minutes.

How to use
- Ops Console (needs AIOps + Advance): open incident → SRE Agent tab
- Incident details page → SRE Agent tab
- Slack incident channel → SRE Agent Triage or @pagerduty + question
- MS Teams: Early Access via @pagerduty
- Optional virtual responder: Incident Workflow (GA path) or Escalation Policy (Early Access)

Example
- Dynatrace pages “Checkout latency high.” You open the Slack incident channel, click SRE Agent Triage. Agent summarizes the payload, finds similar past incidents, flags a recent change event, and recommends your rollback Incident Workflow. You confirm before anything runs.

POC tip
- Upload one service runbook (.md). Ask “What are some likely root causes?” then “Analyze past incidents.” Resolve so memory saves. Cost: 4 AI Actions per ask/nudge. Configure Connectors under AI Settings → SRE Agent (Grafana/Datadog/New Relic/CloudWatch/Confluence/GitHub as available).

---
2) Scribe Agent — meeting scribe

What it is
- Joins Zoom / Microsoft Teams / Google Meet, streams an enhanced transcript, posts a post-meeting summary (decisions, actions, attendees). Feeds status updates and Post-Incident Review drafts.

When to use
- Any major incident bridge where people talk faster than notes.

How to use
- Enable Scribe in AI Settings (US manual; EU often default on)
- Configure meeting platform (Zoom automated captions, etc.)
- Auto-launch (default) when conference URL is on the incident, OR Incident Workflow “Add Scribe Agent”, OR Slack `/pd scribe` / Teams `@PagerDuty advance scribe` → Add Scribe Agent to meeting
- Someone must join the meeting within 15 minutes for auto-join to stick

Example
- P1 Zoom war room. Scribe joins, posts live transcript to the incident Slack channel, then posts a wrap-up summary. You generate a PIR draft that already includes bridge context.

POC tip
- Put a real meeting URL + passcode on a test incident. Map a dedicated channel so humans see transcripts. Limit: 1 Scribe per meeting, up to 10 concurrent. Consumes AI Actions (~6 per 30 min + 2 for final summary).

---
3) Shift Agent — on-call coverage

What it is
- Detects schedule conflicts (especially with Google Calendar), suggests replacements, coordinates coverage requests, updates the schedule when someone accepts.

When to use
- Vacation / OOO overlapping primary on-call; last-minute coverage swaps without spreadsheet ping-pong.

How to use
- Advance + Slack on; schedules you care about must be on escalation **Level 1**
- Optional: Google Calendar Extension
- Advance chat: “I am on vacation June 13. Do I have a conflict?” → Request coverage
- Check My Profile → Notification Rules for shift conflict and coverage request

Example
- Primary blocks Friday OOO on Google Calendar. Shift Agent alerts. Manager requests coverage; a teammate accepts in Slack; override is written automatically.

POC tip
- Free of AI Actions. Test with a Level-1 schedule only. Candidates get ~24 hours (weekends excluded from that window).

---
4) Insights Agent — analytics + weekly tips

What it is
- Answers questions over Incidents / Services / Teams analytics; sends weekly proactive recommendations to managers/admins about platform maturity (for example alert grouping).

When to use
- After a noisy week, before a reliability review, or when leadership asks “is MTTA getting worse?”

How to use
- Auto-on with Advance
- Slack: @pagerduty How has average time to resolve changed over the past 6 months for {Team}?
- Or ask inside Advance chat
- Weekly DMs: link PD ↔ Slack user; Unsubscribe stops DMs only

Example
- Team lead asks about Payments MTTR trend over 6 months. Weekly DM later suggests enabling Dynamic Notifications on three noisy services; click-through opens PD to apply.

POC tip
- Free of AI Actions. Use real Team/Service names you own so you can verify numbers against Analytics UI.

Dynatrace → PagerDuty stack (where agents sit)

Dynatrace Problem
  → PD Problem notification / Events API / Workflow connector
  → PD Incident (optional AIOps Event Orchestration)
  → Page human
  → SRE Agent helps triage (uses PD context; add log/runbook connectors)
  → Scribe records the bridge
  → Insights reviews weekly health
  → Shift keeps next week’s coverage valid

Keep Dynatrace as detect+notify. Keep humans as owners of customer impact. Agents cut toil; they do not replace the primary on-call path.

---
Common mistakes
- Expecting agents without PagerDuty Advance
- Confusing Event Intelligence (noise reduction) with the 4 agents
- Putting schedules on Level 2+ and wondering why Shift Agent is quiet
- Scribe auto-join without a conference URL or without anyone joining in 15 minutes
- Running SRE remediations without human confirmation
- Mixing this product suite with the separate “custom API agent POC” (seq 7)

中文简版 — PagerDuty 的 4 个 AI Agent

结论：官方就是 4 个（2025 秋发布）—— SRE / Scribe / Shift / Insights。Advance 是平台，不算第 5 个 Agent。

| Agent | 干什么 | 什么时候用 | 怎么开/用 | 例子 |
| --- | --- | --- | --- | --- |
| SRE | 活着的事件：摘要、历史、runbook、建议修复 | 刚被 page、要快速 triage | AI Settings 打开；Ops Console / 事件页 / Slack | Dynatrace 告警 Checkout 延迟 → Slack 点 SRE Triage → 建议回滚工作流 |
| Scribe | 进 Zoom/Teams/Meet 记纪要 | 大战会议室 | 开 Scribe；会议 URL 挂在事件上 | 桥接结束后频道里有摘要，方便写复盘 |
| Shift | 值班冲突与找替班 | 请假撞上 Level-1 值班 | Advance+Slack；日历扩展 | OOO 冲突 → Request coverage → 同事接受 → 自动改排班 |
| Insights | 问 MTTR/趋势 + 每周改进建议 | 复盘会前 | @pagerduty 提问 | “Payments 近 6 个月解决时长怎么变？” |

启用：AI → AI Settings → 连 Slack/Teams → 打开四个开关。不要对生产乱调 API；本篇只讲产品 Agent，自定义 API POC 见 seq 7。
