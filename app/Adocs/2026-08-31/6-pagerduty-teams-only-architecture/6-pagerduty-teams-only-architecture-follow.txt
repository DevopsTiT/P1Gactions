================================================================================
WHAT THIS IS
================================================================================

PagerDuty = the incident pager.
PagerDuty Advance = paid AI layer (AI Actions budget). The four named agents live here.
Microsoft Teams only = no Slack. Fine for triage and meeting notes. Weaker for coverage DMs.

Four named agents (Fall 2025 suite) — NOT four separate products:
1) SRE Agent     — live triage / RCA / runbook / human-approved remediation
2) Scribe Agent  — Teams meeting transcript + summary + PIR context
3) Shift Agent   — OOO vs on-call coverage (Slack-first; Teams uses Path B)
4) Insights Agent — MTTR/MTTA/volume Q&A (weekly DMs still Slack-first)

NOT one of the four:
- Advance itself (platform + budget)
- Advance Assistant (chat router)
- Event Intelligence / AIOps (noise reduction)
- PIR drafts / Automation Digest / status updates (helpers that spend Actions)

================================================================================
ARCHITECTURE (5 LAYERS)
================================================================================

Layer 5  Four AI agents
Layer 4  Advance Assistant  (@pagerduty / @PagerDuty advance)
Layer 3  Identity           (linkUser, optional graphAuth)
Layer 2  Teams bot + Graph  (cards, chats, meetings, ChatMessage.Read)
Layer 1  PD core            (Service, Escalation, Schedule, Incident)

POC objects
- Service: poc-pd-ai-agents-test
- Escalation: pages ONLY you
- Schedule: poc-shift-agent on Level 1 of that test EP
- Channel: ONE standard Teams team + channel (private/shared unsupported)

Roles
- PD Owner / Global Admin: enable Advance + agents
- PD Admin: Authorize Teams
- MS / Teams Admin: Graph consent + allow third-party app
- Linked Responder: use agents after enable (if PD team has Advance access)
- No REST API token needed for product agents

Graph (must-have for Advance)
- ChatMessage.Read (Delegated) and/or ChatMessage.Read.All (Application)
- Prefer User.ReadBasic.All; revoke User.Read.All
- Meetings: OnlineMeetings.ReadWrite / ReadWrite.All
- Optional Scribe policy AppId US 05ffe668-5b27-45ff-a64d-b2ed6c475d7a / EU 8f79a561-d2f1-4a1e-8092-c2039043a40e
- Application = Admin consent once; Delegated = each user graphAuth; Hybrid = both

================================================================================
DECISION TREE
================================================================================

Active incident triage / RCA / runbook?  → SRE Agent (Teams Early Access)
Incident bridge / PIR notes?             → Scribe Agent (Teams meeting + chat)
On-call OOO / coverage?                  → Shift = Path B (PD web + Calendar) recommended
Ops health / MTTR trends?                → Insights conversational in Teams
Weekly maturity DMs?                     → Slack-only; document the gap

Shared gate: Advance? + PD Admin + MS Admin → §0 once → POC 1 → 2 → 3 → 4
Always TEST service / Level-1 TEST schedule

1) SRE AGENT — USAGE CASE + STEPS
================================================================================

Architecture: virtual responder on a Service. Reads incident + ~2k chars custom_details + runbook
(<=100 KB .md/.txt/.pdf) + optional Grafana/Datadog/New Relic/CloudWatch/Confluence/GitHub.
Memory saves on RESOLVE. Surfaces: Teams @pagerduty (EA), Incident SRE tab, Ops Console (AIOps+Advance).

Usage case: “Checkout latency high” test incident → Teams ask root causes → upload
poc-checkout-latency.md → analyze past incidents → first steps → READ any remediation → decline on POC
→ Resolve so memory saves.

1) Optional: AI Settings → SRE Agent → one real connector (Dynatrace creates incidents; not the main connector list)
2) Write runbook 5–10 steps (last deploy, problem URL, named rollback)
3) PD web: Create incident on poc-pd-ai-agents-test (no prod routing key)
4) Open mapped Teams channel; confirm incident card
5) @pagerduty What are some likely root causes?
6) Upload/Update Runbook (or PD web SRE Agent tab if Teams EA lacks upload)
7) @pagerduty Analyze past incidents
8) @pagerduty What steps should I take first?
9) If workflow offered: read; approve or decline — never auto-run prod
10) Optional web/Ops Console SRE tab
11) Resolve

Pass: grounded reply; later answer cites runbook; no unconfirmed remediation; follow-up feels more specific
Safety: test Service; no PII in channel; fact-check logs/changes
Cost: 4 Actions per ask

================================================================================
2) SCRIBE AGENT — USAGE CASE + STEPS
================================================================================

Architecture: joins Zoom/Teams/Meet; transcript; wrap-up; PIR context.
Limits: 1 Scribe/meeting; 10 concurrent account-wide; human join within 15 min or auto-join skips.
US often manual toggle; EU may default on.

Usage case: 10-min Teams meeting on test incident → paste URL → @PagerDuty advance scribe →
you join → speak symptom / cause / decision → end → see transcript + summary → optional PIR draft.

1) Confirm Scribe Enabled
2) Optional: Incident Workflow “Add Scribe Agent” on test Service
3) Create test incident
4) Create short Teams meeting; copy join URL (+ passcode)
5) Paste URL on incident meeting field
6) Open linked Teams channel
7) Auto-join OR @PagerDuty advance scribe → Add Scribe Agent to meeting
8) Join within 15 minutes; admit from lobby if needed
9) Speak 2–3 clear lines
10) End meeting
11) Confirm transcript (if chat delivery on)
12) Confirm post-meeting summary
13) Optional: ask Advance for PIR draft
14) Resolve

Pass: Scribe joins; transcript; wrap-up lists decisions/actions/attendees
Safety: warn attendees they are transcribed; keep under ~10 minutes
Cost: ~6/30min + ~2 summary

================================================================================
3) SHIFT AGENT — HONEST TEAMS-ONLY
================================================================================

Intended Slack path: Level-1 + Calendar OOO → conflict DM → Request coverage → Slack accept → override.
Teams-only: do NOT claim that DM path. Use Path B.

Usage case Path B (recommended): poc-shift-agent on Level 1 of TEST EP; Google Calendar Extension;
OOO overlaps window; see overlap in PD web; write override; confirm history; note Slack path deferred.

Path A (best-effort): same setup; ask Advance in Teams “I am OOO <date>. Any on-call conflict?”;
still close with a manual web override.

Path B steps
1) Document: Full Shift Slack DM POC deferred — Teams-only org
2) Create poc-shift-agent; you primary on a known window
3) Attach to Level 1 of TEST EP (not prod)
4) Admin: Google Calendar Extension; you authorize
5) OOO block overlapping the window
6) Confirm overlap in PD web / Calendar
7) Create override for coverage person
8) Confirm schedule history
9) Later with Slack: re-run seq 9 Shift POC

Path A extra: enable Shift toggle; ask in Teams Advance; understand Request coverage may need Slack.

Pass Path B: overlap handled; audit trail; Slack deferred
Safety: never override prod primary; tell the candidate it is a POC; Level-1 only by design
Cost: 0

================================================================================
4) INSIGHTS AGENT — USAGE CASE + STEPS
================================================================================

Architecture: conversational analytics over Incidents/Services/Teams.
On-demand Q&A = Teams GA. Weekly maturity DMs = Slack-first (document gap).
Unsubscribe from DMs (when Slack exists) does not kill Q&A.

Usage case: ask last-week high-urgency count, 6-month MTTR, MTTA this month vs last;
sanity-check vs Analytics UI; do not wait a week for a Teams DM.

1) Confirm Insights Enabled
2) Pick Team + Service with real history (empty test Service → thin answers)
3) Open POC Teams channel
4) @pagerduty How many high urgency incidents were there last week on <ServiceOrTeam>?
5) @pagerduty How has the average time to resolve changed over the past 6 complete months for <Team>?
6) @pagerduty Was MTTA faster this month than last month for <Service>?
7) Compare to Analytics web for the same window
8) Optional: Rate AI Response
9) Note weekly DMs are Slack-only
10) Hybrid later: open any Slack tip on TEST service first (can change prod alert behavior)

Pass: number/trend in Teams; roughly matches Analytics; DM gap documented
Cost: 0

================================================================================
COMMON MISTAKES
================================================================================

UPDATE AVAILABLE          → MS Admin re-consent ChatMessage read
Agents silent             → Teams not Enabled; missing Advance perms; wrong PD team access
No meeting/chat           → missing OnlineMeetings/Chat scopes or graphAuth
Scribe stuck in lobby     → lobby policy / admit / CsApplicationAccessPolicy
Expect Shift DMs in Teams → use Path B
Expect weekly Insights DM → Slack-only; use on-demand chat
Private channel           → unsupported
Prod escalation on test   → page only you
Claim full Teams parity   → honest result is 3 full + 1 workaround
