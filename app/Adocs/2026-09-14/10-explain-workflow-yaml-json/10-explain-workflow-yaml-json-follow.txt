Explain YAML and JSON (your Dynatrace pack)

Basics:
- YAML and JSON = two ways to write the same structured config
- YAML uses indentation; JSON uses { } and "quotes"
- Prefer upload: *.workflow-template.yaml
- *.workflow.json = twin of the same workflow (easier to diff, harder to edit scripts)

Workflow files (Automations):
- ago-problem-to-pagerduty-only.workflow-template.yaml  → OPEN → PD
- ago-problem-closed-resolve-pagerduty-only.workflow-template.yaml → CLOSE → resolve PD
- problem-*-pagerduty-only.workflow.json → same content as JSON twins

Workflow YAML sections:
1) metadata = apps needed (dynatrace.automations), inputs
2) workflow.title / description / schemaVersion
3) trigger = when it runs (davis-problem + filterQuery)
4) tasks = prepare JS then PagerDuty JS
   - predecessors = order
   - action = run-javascript
   - replace __PD_ROUTING_KEY__

Classic SNOW files (NOT workflows):
- silvastg-problem-notification.settings.json = Settings API for Problem notifications
- monaco yaml/template = optional as-code for same silvastg notification
- sendEvents true / sendIncidents false = ITOM events not ITSM INC

Upload where:
- Workflow YAML → Workflows UI
- Notification JSON → Settings API/Monaco (optional; UI already has silvastg)
- Do not upload both YAML+JSON as two workflows
- Do not treat silvastg JSON as a Workflow Connection
