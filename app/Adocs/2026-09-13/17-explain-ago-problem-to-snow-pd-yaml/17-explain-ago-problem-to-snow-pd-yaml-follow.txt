Explain ago-problem-to-snow-pagerduty.workflow-template.yaml in detail

Verdict: Readable CREATE workflow template. Same logic as problem-to-snow-pagerduty.workflow.json. Problem OPEN → prepare → parallel SNOW INC + PD → cross-link. Wrapper adds version + dynatrace.automations dependency. Replace placeholders; upload as template; also need close YAML for resolve.

YAML vs JSON
------------
YAML: version + dependencies + workflow; scripts in multi-line |
JSON: flat workflow; scripts escaped; has isPrivate/triggerType
Same 4 tasks — pick one format to upload

Trigger
-------

categories/entityTags empty — tune after import

Task graph
----------
prepare-payload
  → create-servicenow-incident (parallel)
  → create-pagerduty-incident
  → cross-link-snow-pd (both OK)

1 prepare-payload
-----------------
Read Problem event; app from tags; assignMap EIP/CCI/default
Severity → P3/P4 + PD severity
Return problemId, dedupKey=dt-problem-<id>, SNOW/PD fields

2 create-servicenow-incident
----------------------------
POST /api/now/v2/table/incident
correlation_id=problemId + caller/group/biz/impact/description
Return sysId + INC number

3 create-pagerduty-incident
---------------------------
POST events.pagerduty.com/v2/enqueue
trigger + routing_key + dedup_key + links/custom_details

4 cross-link-snow-pd
--------------------
PATCH INC work_notes with PD dedup_key + Problem URL + runbook

Placeholders
------------
__SNOW_INSTANCE_URL__, __SNOW_USER__, __SNOW_PASSWORD__
__SNOW_CALLER_SYS_ID__, __SNOW_GROUP_SYS_ID_*__, __SNOW_BIZ_SYS_ID_*__
__PD_ROUTING_KEY__
