Explain the demo flow diagram in plain English

Verdict: One Problem opens → create workflow makes a ServiceNow ticket + PagerDuty page and stamps both with the Problem ID. Same Problem closes → close workflow finds that ticket and stops that page. Dynatrace is the boss; SNOW and PD do not need to sync each other.

Analogy
-------
Smoke alarm = Problem OPEN
Incident report = ServiceNow INC
Page fire crew = PagerDuty
Same alarm number on both = correlation_id / dedup_key
All clear = Problem CLOSED → close report + stop paging

Half 1 — OPEN
-------------
You/Davis open a Problem (has Problem ID like P-12345)
→ Create workflow Execution starts
→ prepare: build packing list (app, group, priority, dedup_key) — no API yet
→ SNOW POST: create INC, set correlation_id=P-12345
→ PD trigger: page with dedup_key=dt-problem-P-12345
  (SNOW and PD run in parallel after prepare)
→ cross-link: write PD key into INC work notes

Half 2 — CLOSE
--------------
You/Davis close the same Problem
→ Close workflow Execution starts
→ resolve INC: search correlation_id=P-12345 → set Resolved
→ resolve PD: send resolve with same dedup_key

Why two Executions boxes?
-------------------------
Create WF = robot A (only on open)
Close WF = robot B (only on close)

Where to look
-------------
T0 Problems list
T1 create Executions
T3 ServiceNow INC + PagerDuty alert
T5 Problem closed
T6 close Executions
T7 INC Resolved + PD resolved

Keys
----
Problem ID P-12345
  → SNOW.correlation_id = P-12345
  → PD.dedup_key = dt-problem-P-12345
