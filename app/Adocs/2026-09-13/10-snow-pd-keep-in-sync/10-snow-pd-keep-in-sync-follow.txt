Keep ServiceNow and PagerDuty in sync (Dynatrace workflows)

Verdict: Dynatrace is the boss. They stay aligned via shared Problem ID keys + create/cross-link on open + resolve both on close. They do not need to talk to each other directly for this design.

Decision tree
-------------
Need SNOW + PD aligned?
  → Same Problem open/close? Use Dynatrace Workflows as orchestrator
  → Keys: SNOW correlation_id = Problem ID
          PD dedup_key = dt-problem-<ProblemID>
  → Open: create INC + PD in parallel, then cross-link (PD key in INC work notes)
  → Close: find INC by correlation_id, resolve INC + PD with same dedup_key
  → Live assignee SNOW↔PD? Optional native product sync — not required for v1

Short takeaway
--------------
Who syncs them? Dynatrace Workflows
Shared identity: Dynatrace Problem ID
SNOW key: correlation_id = Problem ID
PD key: dedup_key = dt-problem-<ProblemID>
Open: parallel create + cross-link-snow-pd
Close: resolve both with those keys

What sync means
---------------
Create together: yes
Same links/story: yes
Find each other later: yes (keys + work notes)
Close together: yes
Assignee/ack mirror: no (optional later)

Open flow
---------
prepare-payload
  → create-servicenow-incident  ─┐
  → create-pagerduty-incident   ─┴→ cross-link-snow-pd

Close flow
----------
Problem CLOSED → find INC by correlation_id → resolve INC → PD resolve(same dedup_key)

Checklist
---------
- One INC + one PD for one Problem
- correlation_id matches Problem ID
- dedup_key is dt-problem-<same id>
- INC work notes show PD key + Problem URL
- Problem close resolves that INC and that PD page

Common mistakes
---------------
- Random UUID as dedup_key → cannot resolve later
- Wrong/empty correlation_id → close cannot find INC
- Only create workflow uploaded → tickets stay open
- Expecting SNOW to auto-close PD → Dynatrace close WF must do both

Data flow
---------
Problem OPEN → INC (correlation_id) + PD (dedup_key) → cross-link notes
Problem CLOSED → resolve INC + resolve PD (same keys)
