Dynatrace Workflow best practices

Verdict: One job per workflow, filter triggers, keep secrets out of Git (Connection for SNOW), use stable Problem ID keys, test open+close in non-prod, then tighten for prod.

Design
------
- Separate open create vs close resolve (two workflows)
- Clear names; simple graph: prepare → parallel → sync
- Stable keys: correlation_id=ProblemID; dedup_key=dt-problem-<id>

Triggers
--------
- Filter severity/tags/env for prod
- Correct onProblemClose true/false
- Lab first with wider filters; tighten later

Secrets
-------
- SNOW: Dynatrace Connection (not password in YAML)
- PD key: secret or UI-after-import — not in Git
- OK in Git: assignMap, runbooks, sys_ids (config)

Reliability / safety
--------------------
- Never random new dedup_key each run
- Cross-link after both creates
- Demo on non-prod / demo PD service
- Watch Executions when red

Avoid
-----
- Secrets in Git
- Upload YAML+JSON for same job
- Merge open+close into one file
- No filters in prod
- Test create only (forget close)

Your checklist
--------------
[ ] Two workflows
[ ] Connection for SNOW
[ ] PD key not in Git
[ ] Stable keys
[ ] Prod filters
[ ] Open+close demo passed
[ ] Owner known
