PC Queue Health — what the DQL does

timeseries status_series = avg(guidewire.messaging.status),
  filter: { app == "pc" },
  by: { queue.id, queue.name }
| fieldsAdd status = arrayLast(status_series)
| fieldsRemove status_series, timeframe, interval

This run: 16 records, 10/29/2026 11:28:30, timeframe 09:28:00 to 11:29:00.

Line by line
1. timeseries builds a metric line for the selected time window. This is not a log search.
2. avg(guidewire.messaging.status) averages that Guidewire messaging-status metric in each time bucket. status_series is the name of the whole line.
3. filter app == "pc" keeps PolicyCenter only. PC is the usual Guidewire name for PolicyCenter. The filter is inside the timeseries command.
4. by queue.id, queue.name makes one line per queue.
5. arrayLast takes the newest point on that line and stores it as status.
6. fieldsRemove hides the full line, the timeframe, and the interval, so the table is the queue plus that latest status.

16 records means 16 queues had this metric in the window.

The chart beside the editor is titled BC Failed Messages and sits at 0. BC is the usual name for BillingCenter. The query text filters pc. Check the Visual tab if that title is supposed to describe this query.

The query does not define what the status number means. Look up guidewire.messaging.status in Dynatrace Metrics for that.
