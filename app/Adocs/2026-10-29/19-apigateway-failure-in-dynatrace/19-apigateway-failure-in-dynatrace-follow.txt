The Edit Search dialog is the count behind APIGateway FAILURE.

The search is a pivot. It counts the data model APIGW1015_Failure_count for the dashboard time. That model keeps events matching:

index=eip1015 sourcetype=eip_mediator_serverlog Status=FAILURE

The log file is /opt/softwareag/log/1015/apigw5500/server.log. A sample line uses Status: SUCCESS, so a failure line uses Status: FAILURE.

count(RootObject) is the big number. The long AS name is the dataset id. There is no split, so the result is one number.

Time Range is Shared Time Picker (searchByTimer). On the helper page that picker is Last 15 minutes.

Auto Refresh Delay is 1 minute. Refresh Indicator is a progress bar. Apply saves the panel. The red color is set on the chart, outside this dialog.

Create the same tile in Dynatrace.

First check the log. Notebooks, time picker Last 15 minutes:

fetch logs
| filter contains(log.source, "apigw5500/server.log", caseSensitive:false)
| limit 5

No rows means the file is not in Dynatrace yet. Add a log ingest rule for that path, then run the check again.

Then:

1. Dashboards, create a dashboard.
2. Time picker Last 15 minutes.
3. Auto-refresh 1 minute.
4. Add a DQL tile. Paste the query.
5. Single value, field failure_count.
6. Title APIGateway FAILURE.
7. Color: 1 and above is red. 0 stays calm.
8. Save.

data record(failure_count = 0)
| append [
    fetch logs
    | filter contains(log.source, "apigw5500/server.log", caseSensitive:false)
    | filter contains(content, "Status: FAILURE", caseSensitive:false)
    | summarize failure_count = count()
  ]
| summarize failure_count = sum(failure_count)

Leave from: off fetch logs so the tile follows the dashboard time picker. The planted 0 keeps an empty window at 0. If the number ignores the picker, add from: now()-15m on the inner fetch logs.
