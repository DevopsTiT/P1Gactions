Paste a real entity id into dt.source_entity. The form cannot mark that field as required.

For a log-phrase alert, create one custom device and reuse it.

curl -X POST "https://YOUR_ENVIRONMENT.live.dynatrace.com/api/v2/entities/custom" -H "Authorization: Api-Token PASTE_TOKEN" -H "Content-Type: application/json" -d "{\"customDeviceId\":\"alj-sa-support-batch\",\"displayName\":\"ALJ SA Support Batch\",\"type\":\"alj-batch\",\"group\":\"ALJ alerts\"}"

The reply has entityId. It starts with CUSTOM_DEVICE-.

On Edit alert, set:
dt.source_entity = CUSTOM_DEVICE-...
No braces.

Keep event.type as CUSTOM_ALERT.
Keep the event name prefix the alerting profile matches.

When the query returns a row, open Problems and search the title. The device is under Affected entities.

Do not paste a production host id onto a batch alert.

Use {dt.entity.host} only when the query keeps that field with summarize by: { dt.entity.host }.
