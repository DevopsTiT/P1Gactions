ServiceNow (SNOW) explained

WHAT
Official IT ticket system (ITSM). PagerDuty pages people; SNOW keeps the record.
Instance example: https://silvastg.service-now.com

MAIN OBJECTS
Incident (INC) = broken now
Problem (PRB) = root cause
Change (CHG) = planned change
CMDB / CI = inventory of servers and apps

KEY INCIDENT FIELDS
number, sys_id, short_description, impact, urgency, priority, state, assignment_group, cmdb_ci, correlation_id

STATES
1 New → 2 In Progress → 6 Resolved → 7 Closed

YOUR PATH (connector not allowed)
Dynatrace → HTTP → SILVA → CMDB check → create INC or skip (retired host)

SYNC
SNOW correlation_id = Dynatrace problem id
PD dedup_key = dt-problem-<id>

APIs
POST /api/now/v2/table/incident
GET  ...?sysparm_query=correlation_id=P-12345
PATCH /api/now/v2/table/incident/{sys_id}  state=6

COMMON FAILS
network error → allowlist silvastg.service-now.com on this tenant
401 → user/roles
no ticket but 200 → SILVA skipped (CMDB)
duplicates → classic notification ITSM still on
